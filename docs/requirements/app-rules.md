# 앱 규칙 개편 요구사항

## 목표

Curbox는 전면에서 실제로 보이는 앱의 사용량을 기록하고, 재사용 가능한 앱 그룹과 독립된 앱 규칙을 조합해 사용을 제한한다. 보호자는 규칙별로 사용시간을 더하거나 규칙을 잠시 건너뛸 수 있다.

## 도메인 구조

### 앱 그룹

- 앱 그룹은 이름과 앱 목록만 가진 중립적인 묶음이다.
- 그룹 자체는 앱을 제한하거나 시간을 적립하지 않는다.
- 선택 목록에는 전면 실행이 가능한 앱만 표시한다.
- 같은 앱은 여러 그룹에 들어갈 수 있다.
- 그룹 사용시간은 현재 구성원 앱들의 사용시간 합계로 계산한다.
- 앱 그룹과 앱 규칙은 이름 변경에도 유지되는 불변 ID를 사용한다. 새 생성과 복사는 새 ID를 발급한다.
- 대상 포함 또는 제외에 참조 중인 그룹은 단순 삭제할 수 없다. 보호자는 참조 제거 또는 의존 규칙 삭제를 명시적으로 선택해야 한다.
- 기여 그룹은 삭제할 수 있지만 참조 ID는 규칙에 남고 해당 규칙은 수정될 때까지 알려진 대상 범위를 허용하지 않는다.

### 앱 규칙

하나의 앱 규칙은 다음 필드를 가진다.

- 이름과 활성 상태
- 적용 요일
- 하나 이상의 시작 시각과 종료 시각
- 적용 범위
- 필수 입력인 사용 가능 시간
- 선택적인 사용 조건
- 선택적인 적립 허용량

별도의 구간 잠금 규칙은 만들지 않는다. 모든 앱을 포함하고 특정 구간의 사용 가능 시간을 0으로 설정하면 같은 동작을 만든다. 제품 문구에서 `야간 잠금`이라는 별도 개념을 사용하지 않는다.

## 적용 범위

- 포함 대상에는 `모든 앱`과 하나 이상의 앱 그룹을 조합할 수 있다.
- 하나 이상의 앱 그룹을 제외 대상으로 지정할 수 있다.
- 최종 범위는 모든 포함 대상의 합집합에서 모든 제외 대상의 합집합을 뺀 결과다.
- 포함과 제외가 겹치면 제외가 우선한다.
- `모든 앱`은 이후 설치되는 전면 실행 가능 앱도 자동으로 포함한다.
- Curbox, 런처, System UI, 현재 키보드는 내부 필수 예외로 둔다. Android 설정 앱은 보호자가 선택할 수 있다.
- 내부 필수 예외는 포함 방법과 무관하게 모든 규칙의 최종 범위에서 제거하고 앱 그룹 선택 화면에도 표시하지 않는다.

## 시간 구간과 요일

- 구간은 시작 시각과 종료 시각으로 입력한다.
- 시작과 종료가 같으면 24시간 구간이다.
- 한 구간의 최대 길이는 24시간이다.
- 자정을 넘는 구간을 지원한다. 요일은 구간이 시작하는 날을 뜻한다.
- 겹치는 구간은 합집합으로 처리한다.
- 별도의 `하루` 선택지는 제공하지 않는다.
- 여러 활성 구간은 현재 사용일의 사용 가능 시간과 보호자 추가시간을 함께 나누어 쓴다.
- 구간 밖에서도 전역 앱 사용량은 기록하지만 해당 규칙의 소비량은 늘리지 않는다.

## 사용일

- 전역 사용일 복원 시각의 기본값은 현지 시각 오전 4시다.
- 보호자는 설정에서 복원 시각을 바꿀 수 있다.
- 복원 시각 변경은 즉시 새 사용일을 시작한다.
- 요일별 허용량은 사용일이 시작한 날짜를 따른다.
- 사용 가능 시간, 사용 조건, 적립 허용량, 보호자 추가시간과 건너뛰기 상태는 새 사용일에 복원된다.

## 사용 가능 시간

- 새 규칙에는 전역 기본 허용량을 넣지 않는다. 보호자가 값을 직접 입력한다.
- 0분은 활성 구간에서 즉시 제한한다.
- 0분보다 크면 현재 사용일의 모든 활성 구간에서 하나의 허용량으로 소비한다.
- 앱이 여러 규칙의 적용을 받으면 모든 규칙이 허용해야 사용할 수 있다. 하나라도 제한하면 잠긴다.

## 사용 조건과 적립

- 사용 조건과 적립은 서로 독립적인 옵션이다.
- 규칙은 하나 이상의 기여 앱 그룹을 참조할 수 있다.
- 기여 사용량은 참조 그룹들의 현재 앱을 합집합으로 만든 뒤 앱별 사용량을 한 번씩만 합산한다.
- 사용 조건의 `n분`은 기여 합집합 전체의 현재 사용일 사용량으로 판정한다.
- 적립은 기여 사용량과 1대1 비율이며 일일 상한은 없다.
- 조건과 적립이 모두 꺼지면 입력한 사용 가능 시간만 쓴다.
- 조건만 켜면 n분을 채운 뒤 입력한 사용 가능 시간을 쓴다.
- 적립만 켜면 입력한 사용 가능 시간에 기여 사용량 전체를 더한다.
- 둘 다 켜면 n분 전에는 정상 허용량이 0이고, n분을 채우면 입력한 사용 가능 시간과 기여 사용량 전체를 쓴다.
- 기여 사용량은 규칙의 활성 구간과 무관하게 현재 사용일 전체에서 계산한다.
- 하나의 기여 앱 그룹은 여러 규칙에 독립적으로 기여한다. 적립 시간을 규칙끼리 나누어 쓰지 않는다.
- 규칙 자신 참조, 순환 참조, 대상과 기여 앱의 중복을 허용한다. 계산은 다른 규칙의 허용량이 아닌 실제 앱 사용량만 사용한다.
- 참조 그룹이 삭제되거나 해석할 수 없으면 해당 규칙은 허용하지 않는 방향으로 실패한다.

## 전면 사용량 추적

- 화면이 켜져 있고 앱 창이 실제로 보이는 동안만 사용시간을 기록한다.
- 분할 화면에 동시에 보이는 앱은 각각 독립적으로 시간을 기록한다. 두 앱이 1분 보이면 각 앱에 1분씩 쌓인다.
- 앱별 원시 사용량을 저장하고 앱 그룹과 규칙 사용량은 그 데이터에서 계산한다.
- 이벤트마다 가시 애플리케이션 패키지 집합을 다시 계산하고 사라진 패키지만 닫는다. Curbox와 System UI 창 자체는 제외하되 함께 보이는 다른 앱 세션은 유지한다.
- 같은 패키지의 여러 창은 한 번만 기록하고 IME, 오버레이와 비 애플리케이션 창은 추적하지 않는다.
- 앱 전환 시 새 규칙을 검사하기 전에 이전 앱 사용량을 반영한다.
- 통계 추적을 꺼도 활성 시간 기반 규칙이 있으면 현재 사용일 판정에 필요한 임시 세션 원장은 기록한다.
- 통계 추적을 끈 기간의 임시 원장은 과거 통계와 동기화 집계에 넣거나 나중에 소급 복원하지 않는다. 활성 규칙도 없으면 원장 기록을 중단할 수 있다.
- PiP 차단은 구현하지 않는다. 보호자가 Android 시스템 설정에서 앱별로 끈다.

## 보호자 예외

### 보호자 추가시간

- 규칙 하나에 실제 전면 사용 할당량을 더한다.
- 같은 규칙에 여러 번 지급하면 누적한다.
- 규칙의 여러 활성 구간에서 나누어 쓴다.
- 대상 앱이 규칙의 활성 구간에서 보일 때만 소비한다.
- 현재 사용일의 복원 시각에 남은 추가시간을 버린다.
- 서로 겹치는 규칙에 각각 지급하면 각 규칙의 할당량이 독립적으로 소비된다.
- 사용 조건 미달과 직접 사용 가능 시간 0인 규칙에도 지급된 추가시간만큼 사용할 수 있다.
- 비활성 구간에도 미리 지급할 수 있지만 활성 구간에서만 소비한다.

### 제한 건너뛰기

- 규칙 하나만 건너뛴다. 모든 규칙을 한 번에 건너뛰는 기능은 만들지 않는다.
- `선택한 시각까지`와 `다음 복원 시각까지`를 제공한다.
- 선택한 시각은 다음 복원 시각을 넘길 수 없다.
- 건너뛴 동안 앱의 전역 사용량은 계속 기록한다.
- 건너뛴 동안의 사용은 해당 규칙의 소비량에는 포함하지 않는다.
- 다른 적용 규칙은 그대로 검사하고 사용량도 계속 소비한다.
- 별도의 사용량 초기화와 혼합하지 않는다.
- 잠금 화면은 현재 거부 중인 규칙들을 보여 주고 보호자가 승인할 규칙 하나를 선택하게 한다. 승인 후 모든 규칙을 다시 검사하며 다른 거부가 남으면 잠금을 유지한다.

## 앱 그룹 변경

앱 그룹을 저장할 때 적용 기준을 선택한다.

- `지금부터 적용`: 변경 이후의 사용부터 새 구성에 반영한다.
- `오늘부터 적용`: 현재 사용일 시작 이후 기록을 새 구성으로 다시 계산한다.

대상 범위에 추가된 앱의 `오늘부터 적용` 사용량은 해당 규칙의 활성 구간과 겹친 기록만 포함한다. 기여 앱 그룹은 현재 사용일 전체 기록을 포함한다.

설정 변경 지연이 적용되면 `지금부터`는 실제 적용 순간, `오늘부터`는 실제 적용 순간이 속한 사용일 시작을 뜻한다. 대기 상태에는 적용 방식만 저장하고 기준 시각은 실제 적용 트랜잭션에서 결정한다.

## 사용량 초기화

- 앱 하나 또는 앱 그룹 하나에서 실행한다.
- 오늘 사용시간과 오늘 실행 횟수를 즉시 0으로 만든다.
- 마지막 사용 시각은 유지한다.
- 그룹 초기화는 현재 구성원 앱 각각을 전역으로 초기화한다.
- 초기화된 앱은 사용량 페이지, 모든 앱 그룹, 대상 규칙과 기여 계산에서 함께 초기화된다.
- 초기화 순간 전면에 있는 앱은 그 순간부터 다시 시간을 쌓는다.
- 초기화 후 앱 실행 횟수도 다시 쌓는다.
- 실행 횟수는 통계와 초기화 대상일 뿐 잠금 조건으로 사용하지 않는다.
- 비밀번호가 설정되어 있으면 새 인증을 요구하고, 경고 후 즉시 실행한다. 설정 변경 지연은 적용하지 않는다.
- 초기화는 현재 사용일 세션에서 제거할 시간과 실행 횟수 차이를 계산하고 하나의 Room 트랜잭션에서 세션과 기존 집계에 그 차이만 반영한다. 같은 달력 날짜의 이전 사용일 데이터와 마지막 사용 시각은 보존한다.

## 관리 잠금과 보호 방식

- 보호자 비밀번호는 기존 제거 방지 비밀번호와 분리한다.
- 비밀번호가 설정되어 있으면 Curbox 관리 화면에 다시 들어올 때마다 재인증한다.
- Curbox 소유 대화상자와 구성 변경은 인증을 유지한다. Curbox가 직접 시작해 결과를 기다리는 단발성 시스템 화면은 보호 콘텐츠를 가린 상태에서 유지할 수 있지만, 다른 앱이나 task 또는 예상하지 못한 focus 손실 뒤에는 재인증한다.
- 비밀번호 최소 길이와 오입력 횟수 제한은 두지 않는다.
- 비밀번호가 없으면 관리 화면, 규칙별 추가시간과 건너뛰기를 인증 없이 사용할 수 있다.
- Device Owner는 사용하지 않는다.
- 접근성 서비스, 오버레이와 일반 Device Admin 기반의 최선형 보호를 사용한다.
- 이 방식은 설정 화면 접근과 제거를 어렵게 만들 수 있지만 키오스크 수준의 완전 차단을 보장하지 않는다.

## 저장소와 마이그레이션

- 앱별 집계 데이터와 현재 사용일의 짧은 전면 세션 기록을 Room에 저장한다.
- 현재 사용일의 시간과 실행 이벤트는 세션 원장이 권위 데이터이며 기존 날짜 및 시간대 집계는 과거 표시, 동기화와 빠른 조회를 위한 파생 데이터다.
- 세션 기록은 임의 분 단위 구간, 건너뛰기, 분할 화면과 `오늘부터 적용` 재계산에 사용한다.
- 현재 사용일 계산에 필요하지 않은 상세 세션은 정리한다.
- Room 스키마 버전을 올린다. 현재 정책의 파괴적 마이그레이션으로 기존 Room 데이터가 지워질 수 있으며 사용자가 이를 승인했다.
- 설정 JSON의 새 필드는 모두 기본값을 둔다.
- 실행 중 상태와 보호자 인증 정보는 기기 로컬에 둔다.
- 앱 그룹과 앱 규칙은 하나의 원자적인 제한 구성 스냅샷으로 검증, 지연 및 적용한다. 대기 변경이 있어도 후속 편집은 현재 적용 중인 스냅샷과 비교해 대기 후보 전체를 교체한다.
- 실행 중 손상된 제한 스냅샷은 마지막 유효 스냅샷을 교체하지 않는다. 콜드 스타트부터 손상된 대상 참조는 오류로 표시하되 알 수 없는 앱까지 임의 차단하지 않는다.

## 기존 UI 재사용

- 기존 Material 시간 선택기와 요일 선택 UI를 재사용한다.
- 기존 `TimeInterval`의 시작과 종료 형태는 재사용하되, 자정 구간을 저장 단계에서 둘로 쪼개지 않고 하나의 구간으로 유지한다.
- 기존 경고 화면의 벽시계 기반 쿨다운을 새 추가시간으로 간주하지 않는다.

## 이번 변경에서 제외

## 수용 기준

1. 22시부터 06시까지, 모든 앱 포함, 사용 가능 시간 0인 규칙이 해당 구간을 제한한다.
2. 여러 앱을 포함한 규칙의 허용량은 앱별 전면 사용시간의 합으로 소비된다.
3. 분할 화면의 두 대상 앱은 각각 사용시간을 쌓는다.
4. 사용 조건을 채우기 전에는 정상 허용량을 사용할 수 없고, 채운 뒤에는 설정에 따라 1대1 적립량을 함께 쓴다.
5. 겹치는 기여 그룹의 같은 앱 사용시간은 한 규칙 안에서 한 번만 계산한다.
6. 한 규칙을 건너뛰어도 다른 규칙은 계속 제한하고, 건너뛴 사용은 해당 규칙에만 청구되지 않는다.
7. 보호자 추가시간은 전면 사용 중에만 소비되고 복원 시각에 사라진다.
8. 앱 또는 그룹 사용량 초기화는 시간과 실행 횟수를 지우고 즉시 다시 누적한다.
9. 앱 그룹의 `오늘부터 적용`은 현재 사용일 세션을 새 구성으로 재계산한다.
10. 모든 적용 규칙 중 하나라도 허용하지 않으면 앱이 잠긴다.
