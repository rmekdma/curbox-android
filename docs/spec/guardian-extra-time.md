# 보호자 추가시간 입력 및 규칙별 허용 사양

이 문서는 잠금 화면과 Curbox 앱의 앱 규칙 화면에서 보호자 추가시간을 지급하는 동작을 정의합니다. 기존 증분(Delta) 및 목표 총량(Target Total) 입력 방식과 규칙별 허용, 지급 대상 선택, 저장 시 재확인 정책을 함께 설명합니다. 사용일과 누적 시간의 이월 정책은 [앱 규칙 사양](app-rules.md)과 [보호자 추가시간 이월 ADR](../adr/0004-rollover-guardian-extra-time.md)을 따릅니다.

## 1. 배경 및 문제 정의

보호자는 새로 더할 시간뿐 아니라 오늘 총 지급량을 직접 입력할 수 있어야 합니다. 예를 들어 현재 30분을 지급했다면 `추가 시간`에 10분을 입력하거나 `총 추가 시간`에 40분을 입력해 같은 결과를 얻습니다.

추가시간을 허용하지 않는 야간 제한 때문에 잠겨 있어도, 다른 사용시간 규칙에 시간을 지급할 수 있어야 합니다. 해당 규칙의 이월 정책에 따라 주말 등 이후 해금일을 위해 적립할 수 있으며, 이 지급으로 야간 제한이 해제되지는 않습니다.

## 2. 규칙별 추가시간 허용

- 각 앱 규칙에 `추가 시간 허용` 옵션을 둡니다. 새 규칙과 해당 필드가 없는 기존 설정은 기본 켜짐입니다.
- 옵션을 끄면 해당 규칙의 직접 지급, 누적 시간 승인, 수동 누적 증가, 추가시간 사용 및 이월에 의한 잔액 생성을 막습니다.
- 끄기와 함께 해당 규칙의 누적 잔액을 0으로 만들고 당일 추가시간 지급 기록을 모두 삭제합니다. 직접 지급과 누적 풀에서 승인한 지급 기록 모두 해당합니다. 허용값 변경과 삭제는 같은 원자적 설정 갱신으로 처리합니다.
- 다시 켜도 삭제한 시간은 복원하지 않습니다. 이후 새로 지급한 시간부터 사용할 수 있습니다.
- 끄기는 더 엄격한 변경으로 즉시 적용합니다. 켜기는 제한을 완화하므로 기존 앱 규칙 설정 변경 지연을 따릅니다. 다른 완화 변경이 함께 있어도 끄기와 삭제를 지연하지 않습니다.
- 다른 규칙의 잔액과 지급 기록, 기본 사용량, 앱 사용 통계 및 건너뛰기 기록은 유지합니다. 허용된 규칙의 이월, 만료 및 누적 구간 초기화는 기존 정책을 따릅니다.
- 끄기 전에 계산한 정산이나 오래된 설정 저장으로 잔액이 복원되어서는 안 됩니다. 다시 켠 뒤 끝나는 과거 작업도 계산에 사용한 규칙, 지급 기록 및 관련 상태를 저장 시점에 재검증하여 오래된 결과를 거부합니다. 허용 상태 이력은 추가하지 않습니다.

## 3. 지급 대상 규칙 선택

잠금 화면과 앱 내부의 추가시간 입력 화면은 같은 대상 목록을 제공합니다.

- 사용 설정과 추가시간 허용이 모두 켜진 모든 앱 규칙을 표시합니다. 현재 앱과의 일치 여부나 현재 적용 시간 구간과 관계없이 선택할 수 있습니다.
- 현재 적용 구간에서 자신의 대상 앱을 차단하는 규칙을 먼저 표시합니다. 현재 실행 중인 앱만으로 차단 여부를 판단하지 않습니다.
- 차단 중인 규칙 묶음과 나머지 묶음 안에서는 저장된 규칙 순서를 유지합니다. 정렬 후 첫 규칙을 기본 선택합니다.
- 다른 규칙을 선택하면 두 입력을 비우고 그 규칙의 최신 기준 총량을 조회합니다. 이전 선택의 늦은 조회 결과로 현재 선택이나 기준을 덮어쓰지 않습니다.
- 지급 가능한 규칙이 없으면 지급할 수 없습니다. 목록 표시 후 규칙 삭제나 허용 변경이 발생해도 저장 시 최신 자격을 다시 확인합니다.

이 목록은 직접 지급에 사용합니다. 기존 제한 건너뛰기 및 누적 시간 승인 대상 목록은 기존 범위를 유지합니다.

## 4. 총량 기준과 양방향 입력

### 4.1 현재 총량

`현재 총 추가 시간`은 선택한 규칙의 정규화된 현재 사용일과 현재 사용일 세대에 **직접 지급한 시간의 합계**입니다. 이미 사용한 직접 지급분도 포함합니다. 누적 풀 잔액, 풀에서 꺼내 승인한 당일 지급분, 다른 규칙이나 과거 사용일·세대의 기록은 포함하지 않습니다. 미래 지급 기록도 현재 총량에 포함하지 않습니다.

예를 들어 직접 지급 20분과 누적 풀 승인 30분이 있으면 입력 기준 총량은 20분입니다. 이 값은 남은 사용 가능 시간과 다릅니다.

### 4.2 계산과 저장

현재 총량을 `T_current`, 새로 더할 시간을 `Delta`, 목표 총량을 `T_target`이라고 합니다.

```text
총 추가 시간 = T_current + Delta       (Delta > 0)
추가 시간 = T_target - T_current       (T_target > T_current)
```

한쪽 필드를 수정하면 다른 쪽을 즉시 계산합니다. 목표치가 현재 총량 이하이거나 계산할 수 없는 입력이면 유도되는 추가시간 필드는 비우고 음수를 표시하지 않습니다. 양수 앞에 `+`를 붙이지 않습니다.

직접 지급은 총량 증가만 허용합니다. 기존 지급 원장을 덮어쓰지 않고 양수 차이만 새 기록으로 추가합니다. 규칙의 추가시간 허용을 끌 때 지급 기록을 삭제하는 동작은 이 원칙의 명시적 예외입니다.

## 5. 화면 및 인증 동작

- 액션과 팝업 제목은 `추가 시간 변경`, 입력 라벨은 `추가 시간`과 `총 추가 시간`입니다. 선택한 규칙의 현재 총량을 표시합니다.
- 두 입력은 처음에 비어 있습니다. 총량 필드의 플레이스홀더에 현재 총량을 표시해 기존 값을 지우지 않고 목표 숫자를 입력할 수 있게 합니다. 입력되거나 계산된 필드가 포커스를 받으면 전체 텍스트를 선택합니다.
- 입력 중에는 에러를 표시하지 않고 `적용` 시 검증합니다. 공백, 0, 숫자가 아닌 값, 정수 범위 초과 및 현재 총량 이하의 목표치는 저장하지 않으며 폼을 유지하고 입력 오류를 표시합니다.
- 기준 조회 중에는 적용할 수 없습니다. 지급 처리 중에는 중복 제출을 막습니다.
- 잠금 화면은 입력 검증 후 기존 보호자 비밀번호 인증을 사용합니다. 인증 취소나 실패 시 지급하지 않습니다. 인증과 저장이 성공하면 이번 지급을 확인하는 동안 잠금 화면을 유지합니다. 확인에서 다른 규칙의 거부가 남으면 최신 사유를 표시하고, 모든 적용 규칙이 허용할 때만 원래 대상 앱을 다시 실행합니다. 확인 실패나 대기 한도 초과 시 화면을 유지하며 저장 없이 다시 확인할 수 있습니다.
- 앱 내부는 기존 관리 인증 세션을 사용하며 저장 시에도 세션 유효성을 확인합니다. 별도 비밀번호 입력을 중복 요구하지 않고 원래 차단 앱을 재실행하지 않습니다.
- 규칙 A에 지급해도 규칙 B의 거부는 유지합니다. 지급 직후 확인에서 다른 거부가 남아 있으면 잠금 화면에 최신 사유를 표시하고 대상 앱을 실행하지 않습니다. 확인 중 홈으로 이동하면 지급은 보존하고 현재 실행 요청을 취소합니다.
- Activity 종료나 Fragment 뷰 종료 시 소유한 지급·선택·인증 다이얼로그를 정리합니다. 종료 후 도착한 콜백으로 창을 다시 열거나 지급 흐름을 재개하지 않습니다.

## 6. 저장 시 최신 기준 재확인

증분과 목표 총량 입력 모두 폼에 표시한 기준을 저장 시점에 확인합니다. 인증, 규칙의 지급 자격, 현재 사용일·세대 및 직접 지급 총량의 검증과 실제 지급은 같은 원자적 설정 갱신 안에서 수행합니다. 사용일 판단에는 갱신이 실제 실행되는 시점의 시간을 사용하며 재시도에서도 다시 확인합니다.

사용일·세대나 직접 지급 총량이 바뀌면 지급하지 않습니다. 최신 기준을 표시하고 두 입력을 비운 뒤 보호자가 다시 입력하고 제출하도록 합니다. 이전 증분을 새 기준에 자동 적용하거나 목표치를 자동 재계산해 저장하지 않습니다. 다시 제출할 때도 해당 화면의 기존 인증 정책을 적용합니다.

규칙이 삭제되거나 사용 설정·추가시간 허용이 꺼지거나 관리 인증이 만료되면 지급하지 않습니다. 오래된 조회 결과나 인증 콜백이 이 검증을 우회할 수 없습니다.

## 7. 범위 제외

- 개별 지급을 취소하거나 목표 총량을 낮추는 편집 및 음수 입력.
- 여러 규칙이 공유하는 전역 추가시간 풀.
- 제한 건너뛰기 기능의 동작 변경.
- Room 스키마 변경과 데이터베이스 마이그레이션. 규칙별 허용 필드는 기존 설정 JSON에 저장하며 누락된 값의 기본값을 보정합니다.
