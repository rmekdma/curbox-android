# 앱 규칙 사양서 (App Rules Specification)

> **문서 목적 및 위치**  
> 본 문서는 Curbox의 앱 그룹 및 앱 규칙의 비즈니스 정책, 도메인 모델, 집합 해석 및 집행 규칙을 정의하는 기능 사양서(Functional Specification)입니다.

---

## 1. 개요 및 도메인 구조

Curbox는 화면 전면에서 실제로 보이는 앱의 사용량을 기록하고, 재사용 가능한 **앱 그룹**과 독립된 **앱 규칙**을 조합하여 사용을 제한합니다.

```
[전면 실행 가능 앱들]
       │ (중립적 묶음)
       ▼
   [앱 그룹] (포함/제외/기여 단위)
       │
       ▼
   [앱 규칙] ─── 요일, 시간 구간, 허용량, 사용 조건, 적립 허용량
       │
       ▼
[최종 사용 판정] (적용 규칙 중 하나라도 거부하면 잠김)
```

### 1.1 앱 그룹 (App Groups)
- **중립적 묶음**: 이름과 앱 패키지 목록만 가지며, 그룹 자체는 앱을 제한하거나 시간을 적립하지 않습니다.
- **선택 대상**: 전면 실행이 가능한(launchable) 앱만 포함합니다. Curbox 내부 필수 예외(Curbox, 런처, System UI, 현재 키보드)는 그룹 선택 화면에 표시하지 않습니다.
- **다중 소속**: 동일한 앱이 여러 그룹에 동시에 포함될 수 있습니다.
- **그룹 사용시간**: 현재 구성원 앱들의 개별 사용시간 합계로 계산합니다.
- **불변 식별자**: 이름 변경에도 유지되는 고유 ID를 사용하며, 복사/생성 시 새로운 ID를 발급합니다.
- **참조 무결성**:
  - 규칙의 포함/제외 대상에 참조 중인 그룹은 단순 삭제할 수 없으며, 참조 제거 또는 의존 규칙 삭제를 요구합니다.
  - 기여 그룹이 삭제된 경우 참조 ID는 남지만, 의존 규칙은 수정 전까지 대상을 허용하지 않는 방향(Fail-closed)으로 동작합니다.

### 1.2 앱 규칙 (App Rules)
하나의 앱 규칙은 다음 구성 요소를 가집니다:
1. **식별자 및 상태**: 고유 불변 ID, 이름, 활성화 여부
2. **적용 요일**: 적용될 요일 집합 (월~일)
3. **시간 구간**: 하나 이상의 시작 시각과 종료 시각
4. **적용 범위**: 포함 대상 및 제외 대상
5. **사용 가능 시간 (필수)**: 규칙이 허용하는 일일 기본 사용 시간
6. **사용 조건 (선택)**: 특정 기여 그룹의 선행 사용 요구량
7. **적립 허용량 (선택)**: 기여 그룹 사용량에 비례한 추가 허용 시간

> **구간 잠금 (야간 잠금)**: 별도의 전용 잠금 규칙 타입을 두지 않습니다. `모든 앱`을 포함하고 특정 시간 구간의 `사용 가능 시간`을 0분으로 설정하여 구간 잠금을 표현합니다.

## 2. 적용 범위 (Scope Resolution)

- **포함 대상**: `모든 앱` 플래그 및 하나 이상의 앱 그룹 조합.
  - `모든 앱` 선택 시 추후 새로 설치되는 전면 앱도 자동으로 규칙 대상에 포함됩니다.
- **제외 대상**: 하나 이상의 앱 그룹.
- **최종 적용 범위**:
  $$\text{최종 범위} = (\text{포함 그룹들의 앱 합집합}) \setminus (\text{제외 그룹들의 앱 합집합})$$
- **제외 우선 원칙**: 포함과 제외에 동일 앱이 겹칠 경우 **제외가 항상 우선**합니다.
- **내부 필수 예외**: Curbox 앱 본체, 기본 런처, System UI, 활성 IME(키보드)는 규칙 설정과 무관하게 항상 최종 범위에서 제외됩니다. (Android 설정 앱은 보호자가 포함/제외를 선택할 수 있음)

## 3. 시간 구간, 요일 및 사용일 (Time & Day Rollover)

### 3.1 시간 구간
- **구간 정의**: 시작 시각과 종료 시각으로 지정합니다.
- **24시간 구간**: 시작 시각과 종료 시각이 같으면 24시간 전체 구간으로 간주합니다.
- **자정 넘김 (Overnight)**: 자정을 넘는 구간(예: 22:00 ~ 06:00)을 단일 구간으로 지원합니다.
  - **요일 소속**: 자정을 넘는 구간이 속한 요일은 **구간이 시작하는 날**을 기준으로 판정합니다.
- **겹치는 구간**: 같은 규칙 내에 겹치는 시간 구간은 합집합(Union)으로 병합하여 처리합니다.
- **구간 밖 사용량**: 규칙의 활성 시간 구간 밖에서 발생한 사용량은 전역 통계에는 기록되지만, 해당 규칙의 허용량을 소비하지는 않습니다.

### 3.2 사용일 (Day Rollover)
- **기준 복원 시각**: 기본값은 **현지 시각 오전 4시(04:00)**이며, 보호자 설정에서 변경 가능합니다.
- **복원 시각 변경 효과**: 복원 시각을 변경하면 **즉시 새로운 사용일이 시작**됩니다.
- **새 사용일 복원 항목**: 사용 가능 시간, 사용 조건, 적립 허용량, 보호자 추가시간, 제한 건너뛰기 상태가 초기화/복원됩니다.

## 4. 사용 가능 시간, 조건 및 적립 (Allowance, Conditions & Earning)

### 4.1 사용 가능 시간 및 다중 규칙
- 새 규칙에는 기본 허용량이 없으며 보호자가 직접 값을 입력해야 합니다.
- **0분**: 활성 구간 진입 즉시 앱을 차단합니다.
- **공유 소비**: 하루 중 여러 활성 구간이 있더라도 하나의 일일 허용량을 함께 나누어 소비합니다.
- **다중 규칙 적용 (Fail-Closed)**: 하나의 앱이 여러 규칙의 적용을 받는 경우, **모든 규칙이 허용해야만 실행 가능**합니다. 하나라도 제한에 도달하면 즉시 잠깁니다.

### 4.2 사용 조건과 적립 (Conditions & Earning)
사용 조건과 적립은 독립적인 옵션이며 기여 앱 그룹을 기반으로 동작합니다:
- **기여 사용량 계산**: 참조된 기여 그룹들의 구성원 앱 합집합에서 앱별 사용량을 1회씩만 합산합니다. 규칙 활성 구간과 무관하게 **현재 사용일 전체** 사용량을 집계합니다.
- **독립 기여**: 하나의 기여 그룹이 여러 규칙에 독립적으로 기여할 수 있으며, 적립 시간을 규칙 간에 나누어 쓰지 않습니다.
- **조합 동작**:
  | 사용 조건 | 적립 허용량 | 동작 방식 |
  | :--- | :--- | :--- |
  | OFF | OFF | 설정된 기본 사용 가능 시간만 사용 |
  | ON ($N$분) | OFF | 기여 그룹 사용량이 $N$분을 달성한 후에만 기본 사용 가능 시간 사용 가능 |
  | OFF | ON | 기본 사용 가능 시간 + 기여 그룹 사용량 전체(1:1 적립, 일일 상한 없음) |
  | ON ($N$분) | ON | 기여 그룹 사용량 $N$분 전에는 허용량 0; $N$분 채운 후 기본 시간 + 기여 사용량 전체 사용 |

## 5. 전면 사용량 추적 및 세션 원장 (Foreground Tracking & Ledger)

- **추적 조건**: 화면이 켜져 있고(`SCREEN_ON`) 앱 창이 실제로 보이는 동안에만 사용시간을 기록합니다.
- **분할 화면 (Split-screen)**: 동시에 보이는 앱들은 각각 독립적으로 시간을 누적합니다. (예: 두 앱이 1분간 동시에 노출되면 각 앱에 1분씩 누적)
- **세션 원장 (Authoritative Session Ledger)**:
  - 현재 사용일 동안의 짧은 전면 세션 기록을 Room DB에 저장합니다.
  - 이 세션 원장이 임의 시간 구간, 분할 화면, 건너뛰기 및 소급 적용 계산의 **권위 있는 원본(Authoritative Data)**입니다.
  - 기존 날짜/시간대별 집계 테이블은 과거 통계 표시 및 동기화를 위한 파생 데이터입니다.
- **앱 전환 처리**: 앱 전환 이벤트 시 새 규칙을 검사하기 전에 이전 앱의 사용 세션을 먼저 플러시/반영합니다.
- **통계 추적 OFF 시**: 통계 추적이 꺼져 있더라도 활성 규칙이 있다면 규칙 판정에 필요한 임시 세션 원장만 기록하고, 과거 통계나 원격 동기화에는 소급 반영하지 않습니다.

## 6. 보호자 예외 (Guardian Exceptions)

### 6.1 보호자 추가시간 (Guardian Extra Time)
- 특정 규칙 하나에 실제 전면 사용 할당량을 즉시 더합니다.
- 같은 규칙에 여러 번 지급 시 누적됩니다.
- 규칙의 활성 구간에서 대상 앱이 전면에 보일 때만 소비됩니다.
- 사용일 복원 시각(기본 04:00)에 남은 추가시간은 소멸합니다.
- 사용 조건 미달 또는 기본 사용 가능 시간이 0분인 규칙에도 추가시간만큼 정상 사용이 가능합니다.

> **참고 (미소진 추가시간 이월 - ADR 0004)**:  
> 기본적으로 추가시간은 복원 시각에 전량 소멸하지만, 앱 규칙에 이월 기능이 활성화된 경우 미소진 보호자 추가시간은 복원 시각에 누적 보관함으로 이월되어 지정된 해금일(예: 주말)에 꺼내 쓸 수 있습니다. 자세한 내용은 [`ADR 0004`](../adr/0004-rollover-guardian-extra-time.md)를 참조하세요.

### 6.2 제한 건너뛰기 (Skip Restriction)
- 특정 규칙 하나에 대해서만 일시적으로 제한 검사를 건너뜁니다. (모든 규칙 일괄 건너뛰기는 미지원)
- `선택한 시각까지` 또는 `다음 복원 시각까지`를 지원하며, 선택한 시각은 다음 복원 시각을 초과할 수 없습니다.
- 건너뛴 시간 동안에도 앱의 전역 사용량은 계속 기록되지만, 해당 규칙의 소비량에는 청구되지 않습니다.
- 동일 앱에 적용되는 다른 규칙은 정상적으로 검사되고 소비됩니다.

## 7. 앱 그룹 변경 및 사용량 초기화

### 7.1 앱 그룹 변경 적용 기준
- **지금부터 적용**: 변경 이후 발생하는 사용량부터 새 구성으로 판정합니다.
- **오늘부터 적용**: 현재 사용일 시작 이후의 세션 기록 전체를 새 그룹 구성으로 재계산합니다.
  - 대상 범위에 추가된 앱: 해당 규칙의 활성 구간과 겹치는 세션만 포함.
  - 기여 그룹에 추가된 앱: 현재 사용일 전체 세션 포함.

### 7.2 사용량 초기화 (Usage Reset)
- 앱 단일 또는 앱 그룹 단위로 실행할 수 있습니다.
- 대상 앱의 **오늘 사용시간과 오늘 실행 횟수를 즉시 0**으로 만듭니다. (마지막 사용 시각은 보존)
- 통계, 모든 앱 그룹, 대상 규칙 소비량 및 기여 계산에 일괄 반영됩니다.
- 초기화 시점에 전면에 열려 있던 앱은 초기화 순간부터 새로 시간을 누적합니다.
- 보호자 비밀번호가 설정된 경우 재인증을 요구하며 즉시 트랜잭션으로 커밋됩니다 (설정 지연 미적용).

## 8. 관리 잠금 및 기기 보호 원칙

- **보호자 비밀번호**: 앱 삭제 방지 비밀번호와 독립적으로 관리되며, 관리 화면 재진입, 규칙별 추가시간 지급, 건너뛰기, 사용량 초기화 시 재인증을 요구합니다.
- **보호 수준 (Best-effort)**:
  - Device Owner/키오스크 모드는 사용하지 않습니다 (개인 기기 복구 불가 위험 회피).
  - 접근성 서비스, 오버레이 화면, 일반 Device Admin을 조합한 최선형 보호(Best-effort)를 제공합니다.
  - 안드로이드 안전 모드(Safe Mode) 부팅, Force Stop, 시스템 순정 설정 등을 물리적으로 완벽 차단하지는 않습니다.

---

## 9. 저장소 및 마이그레이션 불변식

- **설정 직렬화 호환성**: 모든 설정 JSON 필드는 기본값을 가져야 하며, 필드명 변경은 기존 데이터를 유실시키므로 지양합니다.
- **Room 마이그레이션**: Curbox는 `fallbackToDestructiveMigration()`을 사용합니다. 스키마 변경으로 인한 버전 번호 상향은 로컬 세션 및 통계 데이터를 초기화하므로, 사용자 승인 없이 임의로 버전을 올리지 않습니다.
