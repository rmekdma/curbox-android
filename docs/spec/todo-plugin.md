# Todo 플러그인 사양

Todo School 계정, 학습 목표와 감시, Todo 학습시간에 따른 보호자 추가시간의 동작을 이 문서에서 정의합니다. 용어는 [용어집](../../GLOSSARY.md), 구현 경계와 검증 절차는 [플러그인 운영 가이드](../../todo-plugin/docs/learning.md)를 따릅니다.

## 로그인과 계정

- 첫 로그인 화면과 계정 변경 창에서 암호는 처음에 가려집니다. 입력란 오른쪽의 눈 아이콘을 누를 때마다 가림과 표시를 전환합니다. 가려진 상태는 빗금 친 눈, 표시 상태는 열린 눈으로 나타냅니다.
- 수동 로그인에 성공하면 세션과 자동 로그인에 사용할 자격 증명을 기기에서 암호화해 보관합니다. 세션과 자격 증명은 백업·기기 이전 대상에서 제외합니다.
- Todo가 저장된 세션을 거부하면 화면과 감시가 자동 로그인 시도 하나를 공유합니다. 성공하면 세션을 갱신하고 실패했던 조회를 한 번 다시 시도합니다. Todo가 자동 로그인이나 다시 시도한 조회의 인증을 거부하면 수동 로그인에 성공할 때까지 자동 로그인을 멈추고 로그인 필요 상태를 표시합니다. 일시적인 연결·서버 실패 후에는 대기 시간이 지나면 자동 로그인을 다시 시도할 수 있습니다.
- 로그아웃하면 저장된 로그인 정보와 학습 알림을 제거하고 감시를 멈춥니다. 목표와 감시 등록은 계정별로 보존하며 같은 계정으로 다시 로그인하면 재개합니다. 다른 계정의 학습 상태를 현재 계정에 적용하지 않습니다.

## 대시보드와 목표

- 대시보드와 학습 감시는 서울 시간의 오늘을 사용합니다. 대시보드에는 날짜 선택기를 두지 않습니다. 보호자 추가시간의 리포트 날짜는 [별도의 사용일 기준](#학습시간-조회)을 따릅니다.
- 계정 변경, 학습 설정, 자녀별 과목 목표를 각각 열 수 있습니다. 목표는 구독 과목에만 설정하며, 저장으로 과목 구독이 바뀌지 않습니다. 목표는 0부터 99까지의 정수입니다. 별도 설정이 없는 과목의 기본 목표는 국어 6, 수학 5, 영어 8입니다.
- 목표 설정은 창을 열 때의 계정, 세션, 과목이 저장 시점에도 유효할 때 함께 반영합니다. 도중에 기준이 바뀌면 이전 창에서 입력한 값으로 현재 설정을 덮어쓰지 않습니다.
- 구독 과목마다 오늘의 가장 최근 유효한 수치와 목표를 보여 줍니다. 유효한 리포트가 목표를 달성하면 체크를 표시합니다. 목표가 0인 과목은 수치 없이 즉시 완료로 표시합니다. 대시보드와 감시는 이 과목의 리포트를 조회하지 않으며 수동 새로고침과 명시적 재시도도 같은 규칙을 따릅니다.
- 수동 새로고침 실패와 자동 감시 실패를 구분해 표시합니다. 실패 후에도 이미 받은 유효한 오늘 리포트는 유지합니다. 성공한 자녀 목록 조회에서 사라진 자녀는 감시 등록을 해제합니다. 자녀 목록 조회가 실패하면 기존 등록과 학습 데이터를 유지합니다.
- 학습 목표는 대시보드와 감시의 달성 기준입니다. 목표를 바꿔도 Curbox 앱 규칙이나 Todo 학습시간에 따른 추가시간 산정은 바뀌지 않습니다.

## 학습 감시와 알림

- 자녀별로 감시를 시작하고 멈출 수 있습니다. 감시 시작 시 구독 중인 양수 목표 과목을 확인합니다. 첫 유효한 감시 리포트는 알림음 없이 진행 기준을 세웁니다.
- 정기 조회에는 화면이 켜져 있고 잠금이 해제되어 있으며 해당 과목 앱이 단일 전면 앱으로 확인되어야 합니다. 전면 앱을 확인할 수 없으면 조회하지 않습니다. 감시는 단일 전체 화면 앱을 전제로 하며 분할 화면과 다중 창의 포커스 선택을 지원하지 않습니다. 미등록 자녀, 미구독 과목, 목표 0인 과목, 완료 과목은 정기 조회에서 제외합니다. 양수 목표가 완료된 과목도 수동 조회는 가능합니다.
- 초기 조회와 정기 조회는 동시에 진행하지 않고 같은 학습 설정 간격을 따릅니다. 간격 설정은 초 단위이며 과거에 저장한 분 단위 값도 적용합니다. 접근성이나 알림 권한이 없으면 등록을 유지한 채 감시를 일시 중지합니다.
- 유효한 기준을 세우기 전에 자녀 목록이나 리포트 조회가 실패하면 명시적 재시도까지 기다립니다. 대시보드 당겨서 새로고침은 오늘 리포트를 갱신하고 재시도할 수 있는 오늘의 감시 실패도 다시 확인합니다. 수동 로그인에 성공하면 초기 조회를 다시 시작할 수 있습니다. 초기 실패는 앱 재시작, 날짜 변경, 권한 변경, 동일 자녀의 재등록으로 사라지지 않습니다. 기준을 다시 세워도 과거 리포트와 초기 실패 상태는 유지합니다. 유효한 기준을 세운 뒤 일시적으로 실패한 리포트는 조건을 충족하는 다음 정기 조회에서 재시도할 수 있습니다.
- 조회 결과나 알림 처리는 해당 계정, 세션, 등록, 목표, 날짜, 권한이 여전히 유효한 경우에만 현재 감시 상태에 반영합니다. 이전 감시 작업은 새 감시의 진행 상태나 알림을 덮어쓰지 않습니다.
- 등록 자녀마다 상태 알림을 하나 표시합니다. 미완료 과목은 수치와 목표, 완료 과목은 체크를 표시합니다. 상태 알림을 상단 팝업으로 표시할 때도 같은 요약을 사용합니다. 수동 리포트 갱신은 소리 없이 상태 알림에 반영합니다. 자동 로그인에 실패하면 상태 알림의 진행 요약을 화면과 같은 로그인 오류로 바꿉니다.
- 달성 알림은 감시 기준을 세운 후 미완료에서 완료로 바뀔 때만 요청합니다. 달성 알림의 활성화와 소리는 상태 알림과 별도로 설정합니다. 소리를 선택할 때 짧게 미리 들려주고 설정을 열 때는 재생하지 않습니다. 실제 소리와 상단 팝업 표시는 Android 알림 채널 설정을 따릅니다.

## 보호자 추가시간 연결과 당일 지급

### 연결 설정

- 앱 전체에 Todo 연결을 하나 둡니다. 현재 로그인 계정에서 감시에 등록된 자녀 한 명을, 활성 상태이고 보호자 추가시간을 허용하는 앱 규칙 하나에 연결합니다. 이월이 꺼진 규칙도 연결하고 당일 지급에 사용할 수 있습니다.
- 규칙 선택 아래에 **전날 토도 학습시간 추가** 체크박스를 표시합니다. 이월을 켠 규칙과 새로 연결할 때는 기본으로 체크합니다. 기존 연결에 자동 정산 설정이 없으면 켜짐으로 읽습니다. 이월을 끈 규칙에서는 체크를 풀고 비활성화합니다.
- 체크를 끄면 대기 정산을 모두 종료합니다. 다시 체크하면 체크한 사용일부터 정산합니다. 연결한 규칙의 이월을 끄면 체크 상태도 꺼짐으로 저장합니다. 이월을 다시 켠 뒤에는 사용자가 직접 체크해야 합니다.
- 연결 변경이나 연결 해제는 기존 대기 정산을 종료합니다. 이미 지급한 시간과 누적 보관함에 더한 시간은 기존 규칙에 남으며, 이전 지급 이력도 중복 지급 방지를 위해 유지합니다. 새 연결의 정산은 연결한 사용일부터 적용합니다.

### 학습시간 조회

- 당일 지급은 현재 Curbox 사용일, 자동 정산은 끝난 Curbox 사용일의 날짜로 Todo 일간 리포트를 요청합니다. [앱 규칙 사양의 사용일과 복원 시각](app-rules.md#32-사용일-day-rollover)을 사용합니다. 예를 들어 기본 복원 시각을 쓰면 월요일 새벽 4시 전의 당일 지급은 일요일 날짜의 리포트를 조회합니다. Todo가 달력 날짜별로 기록한 학습을 Curbox가 시각별로 다시 배분하지 않습니다.
- 연결된 자녀의 모든 구독 과목에 대해 리포트를 조회합니다. 기타 활동 범주(`etc`)를 뺀 학습시간을 초 단위로 합한 뒤 가장 가까운 분으로 한 번 반올림합니다. 정확히 30초는 올립니다. 목표 달성 여부와 목표 0은 이 계산에 영향을 주지 않습니다.
- 자녀나 구독 과목이 연결 검증 시점과 달라졌거나 과목의 학습시간을 가져올 수 없으면 조회 전체를 실패로 처리합니다. 조회 가능한 과목만 합산해 지급하지 않습니다.

### 당일 지급

- 연결된 규칙의 보호자 추가시간 화면에서 당일 Todo 학습시간 중 아직 지급하지 않은 몫을 제안합니다. Todo로 지급할 수 있는 최대량은 `max(0, 리포트 총 학습시간 − 당일에 Todo로 지급한 시간)`입니다. 직접 지급분은 이 계산에서 빼지 않습니다.
- 보호자는 제안 범위 안에서 Todo 지급량을 승인하고 직접 지급분을 함께 더할 수 있습니다. 인증과 저장 이후 적용 규칙의 재평가는 [보호자 추가시간 사양](guardian-extra-time.md)을 따릅니다.
- 지급량은 계정·자녀·사용일별로 기록합니다. 같은 사용일에 규칙을 다시 연결해도 앞서 Todo로 지급한 학습시간은 다시 지급할 수 없습니다. 지급 출처는 구분해 기록하며 실제 사용량은 보호자 추가시간의 합계에서 계산합니다.
- 실제 지급과 지급 기록을 함께 저장합니다. 저장 시 규칙, 연결, 세션, 등록 또는 사용일이 바뀌어 조회 기준이 유효하지 않으면 이전 제안으로 지급하지 않습니다.

## 자동 정산과 이월

- 자동 정산이 켜져 있고 연결된 규칙이 활성 상태이며 이월과 보호자 추가시간을 허용할 때, Curbox의 사용일 이월 이후 끝난 사용일의 Todo 리포트를 정산합니다. 정산을 켠 사용일보다 앞선 리포트는 소급하지 않습니다.
- [앱 규칙의 이월 주기](app-rules.md#미소진-보호자-추가시간-이월)에 따라 해금일에서 적립일로 넘어가는 경계에는 누적 보관함을 초기화합니다. 이 경계에서는 막 끝난 해금일을 정산하지 않으며, 이전 주기의 대기 정산도 종료합니다. 그 외 전환에서는 종료된 사용일을 정산할 수 있습니다. 토·일이 해금일이라면 토요일분은 일요일에 정산할 수 있고, 일요일분은 월요일에 정산하지 않습니다.
- 기기가 꺼져 있었거나 서비스가 중단됐다가 재개되면 현재 이월 주기에 속한 미정산 사용일을 처리할 수 있습니다. 해금일에서 적립일로 넘어가는 경계가 없는 일정은 주 단위로 대기 정산을 만료시키지 않습니다.
- Todo 정산은 당일 지급과 같은 식으로 **미지급분만** 누적 보관함에 더합니다. 이미 지급한 추가시간의 남은 양은 Curbox 이월 정책으로 별도 처리합니다. 최종 리포트가 이미 지급한 Todo 시간보다 작으면 Todo 정산은 0분이며 이미 지급한 잔액은 그대로 처리합니다.
- 예를 들어 직접 20분과 Todo 30분을 지급받아 추가시간 15분을 썼고, 최종 Todo 리포트가 55분이라면 이월되는 날에는 지급 후 남은 35분과 미지급 Todo 25분을 합해 60분이 더해집니다.
- 리포트 조회가 실패해도 사용일 전환과 기존 보호자 추가시간의 이월은 진행합니다. 유효한 대기 건은 서비스가 동작하는 동안 재시도하며, 정산을 끄거나 연결을 변경하거나 이월 주기가 끝나면 지난 대기 건을 반영하지 않습니다.
- 하나의 리포트는 한 번만 정산합니다. 미지급분이 0분이어도 정산 완료를 기록합니다. 잔액 갱신과 완료 기록을 함께 저장하고, 저장 직전 현재 연결·등록과 규칙의 이월 자격을 확인합니다. 보호자 추가시간 허용을 끈 뒤에는 이전 정산으로 초기화한 시간이나 잔액이 되살아나지 않습니다.
