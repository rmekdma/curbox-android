# 07 — 기존 모델 전환과 제품 수준 검증 완성

**What to build:** 기존 설치가 결정론적이고 멱등인 마이그레이션을 통해 새 앱 그룹과 앱 규칙으로 업그레이드되는 사용자 여정을 완성하고, 새 판정을 유일한 앱 제한 경로로 전환한 뒤 기존 결합형 실행 및 편집 경로와 불필요해진 호환 코드를 제거한다. 각 수직 티켓에서 이미 검증한 다중 프로세스와 서비스 안전성을 전체 회귀 및 세 가지 빌드 변형에서 마지막으로 확인한다.

**Blocked by:** 04 — 사용 조건과 적립 허용량 완성; 05 — 보호자 인증과 규칙별 임시 승인 완성; 06 — 앱 그룹 소급 변경과 사용량 초기화 완성.

**Status:** ready-for-agent

- [ ] 기존 결합형 앱 그룹 설정은 의미를 보존하는 중립 앱 그룹과 앱 규칙으로 한 번만 마이그레이션된다.
- [ ] 기존 ID에서 생성하는 새 ID는 결정론적이거나 완료 표식으로 보호되어 같은 입력이 같은 결과를 만든다.
- [ ] 마이그레이션을 반복 실행해도 중복 그룹이나 규칙이 생성되지 않는다.
- [ ] 새 모델로 옮겨진 뒤 기존 결합형 앱 그룹 판정 및 편집 경로를 더 이상 사용하지 않는다.
- [ ] 오래된 JSON과 새 JSON 모두 기본값 누락이나 알 수 없는 참조 때문에 앱 또는 접근성 서비스가 충돌하지 않는다.
- [ ] 새 앱 그룹, 앱 규칙, 복원 시각과 제한 강도 변경이 설정 변경 지연의 모든 적용 경로에서 동일하게 처리된다.
- [ ] 기한이 지난 설정 변경은 서비스 heartbeat, 앱 시작과 설정 변경 지연 화면에서 모두 적용된다.
- [ ] 각 기능 티켓에서 검증한 설정 소유권, Room 인스턴스, 프로세스 갱신, 오류 격리, 취소 처리와 수명주기 정리를 전체 업그레이드 회귀에서 다시 확인한다.
- [ ] 재부팅, 서비스 재연결과 사용일 복원 경계가 포함된 기존 설치 업그레이드 여정을 검증한다.
- [ ] 현재 사용일 계산에 필요하지 않은 상세 세션 정리와 기존 집계 호환을 최종 회귀에서 확인한다.
- [ ] Room 파괴적 마이그레이션으로 기존 사용 데이터가 사라질 수 있다는 승인된 영향이 릴리스 노트 또는 사용자 안내에 기록된다.
- [ ] 제품 문구는 앱 그룹, 기여 앱 그룹, 앱 규칙, 적용 범위, 사용일, 사용 조건, 사용 가능 시간, 적립 허용량, 보호자 추가시간, 제한 건너뛰기와 사용량 초기화 용어를 일관되게 사용한다.
- [ ] 제품 문구에서 별도 야간 잠금과 별도 구간 규칙 개념을 제거하고 0분 앱 규칙으로 설명한다.
- [ ] Device Owner나 키오스크 수준 보장을 노출하지 않고 접근성, 오버레이와 일반 Device Admin 보호의 한계를 설명한다.
- [ ] 외부 API, 동기화 정책, 백업과 복원, 외부 브로드캐스트, NFC, 앱 설치 통제와 PiP 자동 차단은 변경하지 않는다.
- [ ] 규칙 판정, 시간 경계, 분할 화면, 기여, 보호자 승인, 그룹 소급 변경과 초기화를 아우르는 회귀 테스트 묶음이 통과한다.
- [ ] 접근성 서비스 오류 주입 뒤에도 후속 이벤트가 처리되는 회귀 검증이 통과한다.
- [ ] full 단위 테스트와 full, playstore, fdroid 조립이 모두 성공한다.
- [ ] 지원 기기에서 앱 그룹 생성부터 규칙 차단, 적립, 추가시간, 건너뛰기, 소급 변경과 초기화까지 대표 사용자 여정이 수동 검증된다.
